# Live debug console

The chat console observes existing runtime and streaming boundaries. It does not ask a model to narrate activity or change authorization. Open the terminal icon in chat; the bottom panel can be resized or maximized. It follows the active application theme. Closing it does not stop the turn.

Events use schema version 1 and carry UTC millisecond timestamps, a persistent sequence, owner-scoped conversation and turn identifiers, category, severity, operation, status, correlation identifier and bounded metadata. Model requests, first tokens and completion, observed retries/fallbacks, tool execution, retrieval-classified tools, approvals, context preparation and turn outcomes are recorded where those boundaries are available. Timings use monotonic clocks except approval waiting across separate requests, which uses the recorded wall clock. Provider-reported prefill/generation timing is included only when supplied.

Events are asynchronously buffered and stored in the application data directory in `debug_console.sqlite3`, outside the vault. The queue is bounded; overflow is recorded where possible. Retention defaults to 14 days and 100,000 events, configurable with `MABEL_DEBUG_RETENTION_DAYS` and `MABEL_DEBUG_MAX_EVENTS`; pruning occurs during writes. Abrupt termination or storage errors can lose queued events. Incognito requests are excluded. A best-effort bridge emits non-incognito turn and discovery lifecycle metadata to the Phase 0 ledger.

The authenticated endpoint checks conversation ownership and reads by sequence cursor. The UI polls while open, replays retained history, filters locally, and pages complete turn traces for copy/export. Rendering is bounded; persisted records are not truncated to the rendered preview. Arguments are reduced to safe structural metadata and results to sizes/counts: raw prompts, document contents, paths, credentials and full tool payloads are not persisted. This privacy tradeoff means the console cannot reproduce full tool inputs or results.

Context display previously combined cumulative input tokens from multiple model requests with a percentage based on the current request. The display now separates cumulative reported input from the last request occupancy, using provider usage where available or explicitly labeled message-only estimates otherwise. The latter does not include tool schema overhead. Backend-specific prompt cache, context occupancy, prefill and generation measurements remain unavailable when not reported. Internal embedding/reranker operations, expired approvals rejected before the stream, and all possible retry paths are not separately instrumented.

Verification uses synthetic provider/tool fixtures and Edge headless browser tests; no real vault documents or model calls are needed. The console's SQLite queue is observability only and never an authorization or execution ledger.
