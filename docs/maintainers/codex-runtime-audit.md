## Codex comparison

* [Tool router](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/router.rs): a finalized plan groups the registry and model-visible schemas; structured calls carry names, IDs and arguments. Its discovery/exposure states are distinct from permission. [Registry](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/registry.rs) dispatches through the registered runtime; unsupported calls become model-facing errors, while incompatible payloads may be fatal.
* [Stream handling](https://github.com/openai/codex/blob/main/codex-rs/core/src/stream_events_utils.rs) records tool-call response items before queuing execution, returns call-specific results, and marks the request as requiring follow-up. It distinguishes reasoning, message items and tool results. [Turn processing](https://github.com/openai/codex/blob/main/codex-rs/core/src/session/turn.rs) combines model follow-up requirements with pending input and handles compaction and interruption. These sources do not prove that every reasoning-only provider response necessarily produces a user-facing error; Mabel needs its own explicit terminal contract.
* [Approval stage](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/approvals.rs) checks whether approval is allowed, records decisions and converts denial to a rejected result. An approval is not a blanket capability or an alternative to resource confinement.
* Mabel already has useful pieces: `TurnContract` (`src/turn_contract.py:6342,6431`), authority construction (`src/agent_runtime/authority.py`), request-bound execution (`src/tool_execution.py:1770`), exact approval store (`src/tool_approvals.py`), result normalization/recovery (`src/agent_runtime/tool_recovery.py`), effect/evidence completion (`src/agent_runtime/completion.py`) and saved artifacts (`src/agent_runtime/task_artifacts.py`). `src/agent_loop.py:21053` and `src/clean_agent_preview.py:5262` implement separate agent variants, while chat bypasses both. `src/tool_index.py` supplies optional retrieval and catalog fallback. Keep these security boundaries; a model-visible schema is not a grant.

## Staged migration and rollback

1. **Terminal semantics and evidence.** Define one provider-independent terminal result separating visible final text, reasoning, complete tool calls, failed/incomplete streams and pending approval. Route and save an explicit unsuccessful/incomplete status when no visible answer or executable call exists; never replay tools due to a generation retry. Add production-route tests for reasoning-only, disconnect, partial visible output and both provider transports. Roll back the adapter only if compatibility fails; keep explicit failure diagnostics.
2. **Memory read capability.** Provide a bounded, owner-scoped memory-read operation through the existing manager/dispatcher and existing settings. The model can request relevant recall from conversational context, including a broad overview; use deterministic default fallback only when appropriate. Respect disabled/incognito/owner restrictions, avoid dumping all memory, and handle unavailable vector retrieval. Test no-tool small talk, broad/follow-up recall, no matches, owner isolation and disabled memory. Avoid expanding phrase tables or granting writes.
3. **Shared request lifecycle.** Define a per-request tool plan from actual registered, enabled and policy-eligible tools and their authoritative executable identities. Let Chat and Agent pass different allowed capability policies to the same existing execution lifecycle; preserve existing turn-contract and resource/owner checks, exact approvals and UI session mode. Roll out behind a per-session feature flag, retaining the existing Chat route as rollback. Never infer permission solely from a model call or schema advertisement.
4. **Incrementally converge the compact adapter.** Reuse the same call/result/approval/terminal interfaces and proven provider normalization, migrate one provider/runtime path at a time, replay fixtures in shadow mode without executing side effects, then remove duplicate control code only after parity. Keep separate decoding adapters where model protocols genuinely differ. Test malformed and unknown calls, denied operations with replanning, approval once, cancellation/reconnect, partial effects, regenerate without replay, and existing vault confinement.

No claim is made that a shared loop alone solves memory relevance, local model tool-calling reliability, or permission semantics. The two xfails remain until implementation and should become passing acceptance tests before enabling the new route by default.
